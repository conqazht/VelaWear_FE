## Why this matters

Even after pure helpers and loading renderers move out, `MemberProfile` still
coordinates unrelated account, delivery, orders and favorites UI in one module.
That makes small changes risky, inflates review scope and encourages accidental
coupling between panel-local state. This plan leaves routing, providers, queries
and mutations in the route orchestrator while extracting typed presentation
panels under the protection of FE-009's characterization tests.

## Current state

- At the original baseline, `app/(shop)/profile/page.tsx` was 1,314 lines and
  `MemberProfile` spanned lines 106–1191. FE-009 should reduce it to at most 1,150
  lines by extracting pure utilities and loading UI.
- The top-level tab contract is defined by `profile`, `orders`, `favourites`,
  `coupons`, and `reviews`; URL state uses `/profile?tab=<id>`. Preserve the
  British spelling `favourites` because it is part of the current URL contract.
- At `app/(shop)/profile/page.tsx:106-124`, the route component currently owns
  providers, mutations and queries before rendering every panel:

  ```tsx
  export default function MemberProfile() {
    const { user, isAuthenticated, isLoading: isAuthLoading, checkSession } = useAuth();
    const { locale, t } = useI18n();
    const updateProfileMutation = useUpdateProfileMutation();
    const userId = user?.id;
    const ordersQuery = useOrdersByUserQuery(userId, { size: 100, sort: "createdAt,desc" });
    const addressesQuery = useUserAddressesQuery({ userId, size: 100 });
  ```

  Dependency plans will rename/gate some hooks; preserve the merged orchestrator
  ownership rather than restoring this legacy signature.
- The profile tab contains sidebar panels for account, delivery, visibility,
  communication and privacy. FE-004 must already have removed or disabled mock
  actions and made `/profile/settings` canonical.
- Orders UI originally occupies `app/(shop)/profile/page.tsx:841-945`; favorites
  starts at line 947; delivery UI starts at line 613. FE-008 must already gate
  the associated requests to active panels.
- FE-009 creates and owns:
  - `components/shop/profile/profile-formatters.ts` — pure formatting/metadata.
  - `components/shop/profile/profile-loading.tsx` — loading-only components.
  - `app/(shop)/profile/page.test.tsx` — semantic characterization contract.
- Existing UI conventions use current Card/Skeleton/Select/Popover components,
  Tailwind classes and `useI18n`; this plan must reuse them without visual
  redesign.
