## Why this matters

Opening `/profile` currently requests up to 100 orders and 100 addresses even
when the user is viewing neither section. That spends network, database and
rendering work on hidden panels and makes the default profile view compete with
its own unnecessary requests. This plan keeps hooks unconditional, but uses
explicit query `enabled` gates so data is fetched only when its owning panel is
active and remains cached when the user returns.
